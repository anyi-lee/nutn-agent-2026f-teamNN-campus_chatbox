# 分層 Email 表單

日期：2026-11-02。基準 commit：`65a8517`＋未提交工作樹。這次依使用者最新選擇，以分層表單取代可見的寫信對話；原對話 API 保留相容，但不再顯示於寫信介面。

## 操作與欄位

1. 開啟 Email Agent，單選「處室」或「學系」。
2. 處室：先選處室，再從第二層選該處室所屬組別。沒有細分組別時可選「處室公開窗口（不指定組別）」。更換處室清空舊組別。
3. 學系：先選系所，再選該系已收錄老師；有系辦公開窗口時另行標示。更換系所清除舊老師，不借用別系教師。
4. 填寫自己的姓名（必填）、寄信目的（必填）、年級、自己的系所、詢問內容（必填，至少 5 字）與選填背景。收件系所不自動填入寄件人系所。
5. 產生草稿後可預覽、編輯、複製、另存模板，或「返回修改資料」保留表單重填。
6. 只有獨立勾選確認後才可寫入 Sandbox；不寄真實信箱。返回表單、修改或切換對象後須重新確認。
7. 模擬寄出成功後，當下保留回執供查看／複製；關閉再開啟會回到空白預設表單（處室模式、未選收件人與目的，姓名／系所／年級／內容清空）。已保存模板與後端 Sandbox 執行紀錄不刪除。尚未寄出或寄出失敗的草稿關閉再開啟仍保留。

姓名／系所／年級為自由填寫欄位；寄信目的保留原選項（專題名額、研究方向、課程問題、預約、加簽、補交、答案／解題、成績、其他）。處室與學系互斥，避免同時指定兩個收件類型。

查詢回答的「寫信給對方」仍保留，會預選分類、系所與收件人。若已有不同對象的未完成信件，先確認切換；切換時清除詢問事項與待確認草稿，保留寄件人的姓名、系所與年級。既有帳號、常用文字與完整模板功能保留。

## 名單與安全界線

- `ui/email_directory.json`：由官方快照編譯的公開名稱／分類，不含 Email、API Key 或私人資料。
- 單位清單：22 筆教學單位／學程、51 筆處室／組別。並非每個入口都已取得信箱。
- 收件人（2026-11-03 更新）：191 筆教師所屬／信箱關聯（182 組不同姓名／信箱）、23 個單位窗口。原國文系 10 位保留，另外沿 16 個入口補入 147 筆；[逐系來源與未補齊項目](faculty_source_audit.md)。跨系支援教師在各所屬選單分列，相同姓名／信箱不構成假歧義；不同信箱仍需澄清。介面只接受同時存在此分類檔與目前 `/api/config.teachers` allowlist 的對象；表單資料中的信箱不由瀏覽器決定。
- 選到未收錄信箱的處室或尚未收錄師資的系所時，顯示原因與官方入口，不產生猜測信箱的草稿。
- 分類檔只影響名單展示；實際送到 `/api/email-draft` 的仍是既有 `teacher_name`、`purpose`、寄件欄位、事項與已確認 memory selections，`recipient_mode` 不送入工具契約。
- 產生時鎖定欄位並阻止重複送出。reset／登出後丟棄過時回覆，解鎖欄位，不讓舊草稿恢復。
- 查詢輸入框清空、中文 IME 保護與失敗還原沿用上次修正。

### 舊草稿教師姓名相容（2026-11-03）

全校師資加入跨系支援後，同一人可能顯示為「許世昌（電機工程學系）」與「許世昌（智慧製造在職學位學程）」。舊草稿仍存「許世昌」；原 Read Tool 視為多筆，服務又錯誤顯示為「找不到完全相符的姓名」，導致勾選套用失敗。

現在僅在原姓名完全相符、目前官方有效資料的公開信箱一致時，將舊姓名對應到目前正式收件資料。不同信箱不合併，回傳 `AMBIGUOUS_TEACHER`（409）與候選系所，要求明確選擇；原本指定完整系所名稱仍可精確選取。舊草稿的主旨／正文／姓名欄位與版本不自動改寫，不必刪除或重存。套用仍查驗帳號所有權，且不等於同意寄送。

驗收：200 項 Python／HTTP、前端 22＋25 組全通過。新增 6 項隔離帳號／SQLite 測試，涵蓋舊姓名、明確所屬、同名不同信箱、未知姓名、人工確認／冪等及帳號隔離；瀏覽器也實際登入合成帳號並成功勾選舊草稿，保留原文且寄送確認未勾選。此次模型為 `LIVE_NOT_RUN`。使用者已在後端修正後重啟服務；重新整理網頁即可重試。

## 維護名單

### AI 修改時的收件人鎖定（2026-11-03）

繼舊草稿套用修正後，AI 修改流程的嚴格字串判斷也會把模型省略系所後綴的同一人視為換人，顯示 `Gemini changed the user-confirmed teacher`。現在工具 schema 的 `teacher_query` 以 enum 限定原選定的完整名稱，系統提示也要求保留系所。

若模型仍只回傳同一人的完整姓名，只有在該姓名由 Host 從目前選定官方紀錄提供、且完整名稱確實是其系所修飾顯示時才接受；執行工具時一律改用原先選定的完整識別，不拿模型回傳值另找其他對象。另一位老師、只給姓氏、不同系所標籤或單位簡稱仍拒絕。Manual／LangChain 共用檢查；trace 分別記錄 `model_arguments`、實際 `arguments` 與 `query_normalized`，不以模糊比對放寬收件界線。

最新離線／HTTP 回歸 207 項、前端 22＋25 組通過。7 項新增測試使用明示 provider double，涵蓋省略系所、不同人／不同系所拒絕、真實 Host 到 adapter 流程、同一筆 teacher ID／信箱／署名與重新確認；不把替身的成功欄位當真實 Live 證據。

### 處室兩層選單規則

分類檔版本為 `email-directory-v2`，行政單位新增 `parent_office`；以原官方快照中明確的處室名稱前綴建立關係。第一層只列處室，第二層才列該處室的組別／窗口。使用者必須選第二層才構成完整收件人；點擊既有回答的寫信入口則可直接預選兩層。

組別沒有已驗證信箱時停止，不自行使用上級處室信箱。若使用者要改寫給處室公開窗口，須明確選該項目，仍需另外確認草稿與 Sandbox。僅有電話分機的組別可見但不能假造可寄信的能力。這次不改寄件人資料欄位，也不需重貼 Key。
