## 範圍與已知限制

從「僅資工系」擴充為全校公開單位入口與已收錄師資，不把未抓到的資料當作不存在，也不把單位名錄當成完整校務知識庫。

- 名錄：73 筆教學／行政單位及公開分機表組別。
- 可驗證收件人：34 位教師（原資工 8 位＋新增電機／材料／生態等 26 位）、23 個單位公開窗口（含原資工系辦）。不是全校完整師資名單。
- 可回答：官方入口、已收錄電話／分機、已收錄公開信箱，以及來源實際包含的教師資訊。
- 目前無法保證：完整課表、服務時間、現任主管姓名、辦理規定／截止日期、全校每一位教師聯絡方式。沒有證據時會停止、追問或附官方頁面。
- 圖書館固定時間等尚未收錄的資訊會回傳 `insufficient_evidence`；這是範圍限制，不是已完成的時間查詢。
- 收件人永遠從伺服器載入的官方記錄解析，不能將使用者隨手輸入的信箱直接變成 Write Tool 收件人。

## 寫信互動

1. 開啟 Email Agent，直接說需求，不顯示原本的新信表單。
2. Gemini 可用時抽取原文片段；未設定時明示使用有限的基本比對，失敗時標示 fallback。模型不能編造個人背景或直接提供收件地址。
3. Host 查核唯一官方收件人。缺少對象、事項或署名就追問；多位「林老師」不自動選一位。
4. 資料齊全後使用既有 Read Tool／草稿流程。單位使用「承辦人您好／貴單位」，不一律稱老師。
5. 顯示收件地址、主旨、正文。可編輯、複製或另存為自己的模板。
6. 另行勾選人工確認才能執行 Sandbox Write Tool。不寄送外部郵件；相同 request 重送回傳相同 receipt，不重複寫入。

範例：

```text
使用者：我想寫信
系統：寫給哪位老師或哪個單位？
使用者：國文系
系統：想詢問或告訴對方什麼？
使用者：詢問下學期轉系申請需要準備哪些文件
系統：署名用什麼名字？也可補充系所與年級。
使用者：我叫測試同學
系統：顯示草稿（未寄送，未自動填入國文系作為寄件人系所）。
```

可改用「幫我寫信給電機系盧陽明老師，詢問研究室專題名額」。尚未收錄的老師會要求完整姓名／系所或提供官方確認管道，而不是套用其他人的信箱。

## 輸入／輸出與狀態

新增端點 `POST /api/email-conversation`，沿用 HttpOnly browser cookie、`X-CSRF-Token` 與 session generation：

```json
{"session_id":"本次session","generation":0,"turn_id":"email-唯一回合ID","message":"我想寫信給國文系"}
```

不接受 client 指定 `to`、`confirmed` 或內部收集欄位。回傳 `status`、`answer`、`conversation.awaiting`、`analysis`、`citations`、`session`；資訊齊全時合併既有 `draft_created` 草稿契約。`analysis.live_status` 只描述本次需求理解階段，草稿模型結果另見 `generation`，不能混成同一次 Gemini 成功。

每則最多 2000 字，每封最多 12 個使用者回合；「取消／重新開始」清空本封狀態與待確認草稿。相同 turn ID＋相同訊息重試回傳同一結果，不同訊息則 `409 EMAIL_TURN_CONFLICT`。新訊息使前一份此對話草稿失效；完成／取消後重寫仍需重新確認。

短期對話只保留伺服器程序記憶體，與 cookie owner 隔離；新增對話、登出／登入、來源變更清除。重啟伺服器不保留尚未完成的對話。對話內容不自動寫入長期記憶；保存模板仍須原有確認。模型呼叫期間 reset 或換帳號，舊回覆與草稿不得復活。

## 啟動與操作

在 repository 根目錄執行：

```bash
python3 app.py
```

開啟 `http://127.0.0.1:8000/`。此方式不設定 Key，畫面會標示基本比對／本機模板。要測試 Gemini，沿用既有隱藏輸入啟動腳本：

```bash
bash scripts/run_with_gemini.sh
```

如 8000 已有本機測試伺服器，先在該伺服器終端按 Ctrl+C，再以腳本啟動；不要直接把 Key 當成終端指令。不要在聊天、簡報、截圖或 Git 提交 Key。

這次未將既有 API Key transport 改為 Google Cloud／ADC；課程期中要求的 ADC 主流程仍是獨立待補驗證項目，不能因本次測試通過而宣稱符合。

### 回答接續寫信與輸入框修正

一般教師查詢、以記憶找到的有效教師，以及有公開信箱的已收錄單位，都可直接由回答的「寫信給對方」進入對話。不再要求問題先包含「寄信／Email」字樣；候選須存在伺服器提供的收件人設定，不能從回答文字擷取任意信箱。不同收件人的既有對話／草稿須先確認清除，開啟按鈕本身不產生草稿、不寄信。

校務問題與寫信訊息送出時立即清空輸入。網路失敗僅在輸入框仍空白時還原原文，不蓋掉使用者已輸入的下一則文字；reset 後也不還原舊對話。中文選字的 Enter（composition 或 keyCode 229）不當成送出，Shift+Enter 保留換行。這次僅前端更新，重新整理即可，無須重新設定 Key 或重啟服務。

後續補驗證：設定可用模型／ADC transport 後，以同版本重跑教師及單位各一條 Gemini 理解→Read Tool→回填模型→草稿→人工確認→Sandbox，另存日期、commit 與 `LIVE_PASS`／`LIVE_FAIL`。擴充師資或服務時間必須先補官方來源與對應測試。
