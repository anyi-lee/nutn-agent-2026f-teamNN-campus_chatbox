# W7 範本與套用效果：手動真實功能驗收

版本：2026-10-29，candidate `967ee1ef8e484a41250688474dbcaba7c3139896`。請記錄自己的執行時間及結果。本文件為手動測試步驟，不是已完成的瀏覽器或 Gemini Live 證據。

## 啟動

在 Repository 的 PowerShell 執行 `python app.py`，開啟 `http://127.0.0.1:8000`。若原服務尚在執行，先 Ctrl+C 停止再重啟；瀏覽器 Ctrl+F5 更新。未設定 Gemini Key 時，實際呼叫本機後端及 SQLite，但草稿使用本機模板，模型狀態為 LIVE_NOT_RUN。

如果出現「常用內容參數不合法」，已確認的一種原因是舊 Python 程序仍在執行，但靜態介面已讀到新版。僅重新整理頁面不會重載後端。請於原終端 Ctrl+C 後重新執行 `python app.py`，再 Ctrl+F5、重新登入並產生新草稿。帳號與已保存內容仍在 SQLite；尚未保存的草稿不跨重啟保留。新版 `/api/config` 提供 `memory_contract=private-draft-revision-v3`，新版介面會在版本不符時停止保存並明確提示重啟。

## 自己的常用文字

1. 訪客可查詢、產生新信，但不能讀寫個人常用文字；介面不應有任何公版區。
2. 登入合成帳號，在「常用內容」新增自介、詢問段落或署名，勾確認後保存。
3. 開啟新信表單，選教師並填本次需求；勾自己的文字，按「預覽套用效果」。對象／目的不變，顯示將加入的文字。
4. 未確認不能套用；選取變更但未套用不能產生草稿。確認套用後產生草稿，只應出現選定文字。
5. 另一帳號看不到以上私人文字。

## 從微積分草稿另存整封模板

1. 登入，開啟 Email 表單，自行選擇實際對應的教師（系統不推測誰教微積分），目的選「詢問題目答案或解題說明」。若正式資料未涵蓋老師，需另補來源，不能假借現有教師身分。確認表單上已沒有保存入口。
2. 填合成姓名，詢問內容填「想請問本次微積分 Practice 的參考解答或解題說明是否方便提供？」，按「產生草稿」。
3. 在草稿預覽直接修改主旨／正文，例如主旨「微積分 Practice 解答詢問」，正文調整為滿意的語氣與署名。按「草稿另存為模板」，應帶入剛修改的主旨及完整正文，而不是先前表單內容。
4. 命名「微積分 Practice 固定詢問」，檢查教師／主旨／正文，勾保存確認。沒有勾確認就不保存；未登入不能另存。
5. 新對話開啟 Email 草稿助手，在上方「套用已存完整草稿」勾選一份。應直接驗證官方收件人並建立新草稿，呈現信件樣式的教師／主旨／完整正文，不跳「常用內容」，也不另外要求確認套用。套用時不需填姓名、目的或系所。
6. 要補「本次是 Practice 3，第 2 題」時，按「編輯本次信件」才展開編輯器。編輯完按「確認修改並更新草稿」，應保留逐字主旨／正文、不呼叫模型潤稿。選另一份時應切換且只勾一份；套用失敗保留目前信件。取消勾選應返回新信表單，寄送勾選清除。
7. 另外勾選收件人／主旨／正文確認後才可寫入 Sandbox，無真實外部 Email。若再編輯任何內容，原寄送勾選會清除，先「確認修改並更新草稿」再重新勾選。
8. 重新登入或重啟後，私人模板仍應存在。可保存多份草稿，每次引用一份；沒有公版。舊表單模板保留於管理清單，但不再列入引用選項，可刪除或改存一般文字。

## 引用整封模板後請 AI 調整

1. 引用自己的完整草稿，確認畫面顯示原主旨及正文。
2. 在「讓 AI 完善這封信」輸入「本次是 Practice 4 第 2 題，想請教解題思路；語氣簡短禮貌，保留自介與署名」，按「請 AI 調整」。有手動修改時會先更新草稿，以該版本作為模型來源。
3. 模型執行期間不能重複調整或寄送；完成後檢查新版主旨、正文及原官方收件人。原保存模板不應變更。
4. 新版需重新勾寄送確認才可寫 Sandbox；若喜歡新版，可另外命名保存成另一份模板。
5. 沒有可用 Gemini 設定時，應顯示 MODEL_NOT_CONFIGURED／LIVE_NOT_RUN，原草稿保留。已呼叫但模型失敗時為 LIVE_FAIL，不得假稱本機文字是 AI 新版。
6. 真實驗證須在啟動後端前設定授權的 GEMINI_API_KEY；此功能使用既有 Gemini 客戶端與教師 Read Tool，不代表已完成 Cloud／ADC。檢查 provider／tool_trace 與實際主旨正文後才記 LIVE_PASS；本次自動測試使用明確標示的離線模型替身。

## 邊界案例

| 操作 | 預期 |
| --- | --- |
| 在助手中切換完整草稿 | 一次只勾一份，直接呈現新的完整信件 |
| 切換草稿的請求失敗 | 保留原信件與原選取，顯示錯誤 |
| 取消完整草稿勾選 | 返回新信表單，不寄送也不刪保存模板 |
| 預覽後修改表單再確認 | 要求重新預覽，不套用舊預覽 |
| 預覽後取消選取變更 | 原表單不變，恢復先前已套用的選取 |
| 只選文字範本 | 對象、目的與原表單不變，所選文字在最終草稿出現 |
| 保存自己的文字但未確認 | 不建立私人紀錄 |
| 跨視窗更正或刪除已引用模板，再送舊草稿 | 版本／存在性檢查拒絕；重新產生草稿 |
| 重啟服務、重新登入 | 自己的段落及整封模板仍存在；原待確認草稿不恢復 |
| 草稿編輯後尚未更新 | 清除寄送勾選並禁止寄送；更新後也需重新勾選 |
| 更新後使用舊 draft_id | 後端拒絕舊草稿，只有新 ID 可在確認後寄送 |
| 重用整封模板 | provider 為 saved_draft；不呼叫模型，維持 LIVE_NOT_RUN；原表單產生新信仍可測 Gemini |

## 證據與模型狀態

拍攝：勾選前表單、套用預覽、套用後表單、最終草稿及一個失敗案例。註明日期、版本、預期／實際結果，使用合成資料且不錄帳密或憑證。

自動測試使用真實隔離 SQLite／Host／本機 HTTP 與 JS VM，沒有真實模型或瀏覽器畫面驗證。若自行設定 Gemini Key 驗證，必須確認回應 provider、工具往返及錯誤備援；無呼叫為 LIVE_NOT_RUN、呼叫失敗為 LIVE_FAIL、成功才為 LIVE_PASS。現有 Key 呼叫不是課程 Google Cloud／ADC，ADC 接入仍待補。
